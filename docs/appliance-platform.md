# Owner-bonded Pi system observations

Interlink reads cached card/drive previews, Pi space after the protected2GiB
reserve and signed-update readiness through the existing authenticated control
channel. It displays source and Pi destination together. Camera count/size stay
unavailable until the camera service supplies a preview. Counts include previous
imports and may have changed since the scan; they are not new transfer totals.

`POST /api/v1/appliance/platform` accepts only `{peerId}` through the phone's
authenticated local node. The node signs `ReadAppliancePlatform` for the retained
paired identity/certificate over `covalent-appliance/1`. The Pi requires its
separate controller bond before accessing the platform bridge and rechecks the
full current pairing/bond after the host read. Revocation during a read refuses
the result. No new network listener, trust-by-discovery or remote mutation exists.

`NodeRuntimeConfig.appliance_platform` is an optional explicit read-only native
host hook. Ordinary nodes default to unsupported. One bounded async read per
bond store refuses overlap; eight seconds bounds the host future. The Android
Pi adapter uses a fixed private local socket, kernel-verified root peer, a fixed
read action,32KiB response bound and seven-second whole-response deadline. The
Pi projects its existing services into the contract; no credential, auth URL,
raw error, arbitrary path or source filename crosses it.

The protocol binds device/controller identities and the bond generation.
Unsupported bridge, unavailable bridge, unavailable volume/camera services,
unknown space/update state, disconnected source and incomplete scan remain
distinct. Unavailable observations use required nulls. Both native and Android
validate exact schemas/types, bounded source/label/counts, expected destinations
and false import-approval/source-cleanup capabilities. The dashboard refuses
mixing generations or publishing results after a newer Pi selection. Connection
loss clears old source counts rather than leaving them looking current.

`sourceId` is a scoped opaque display reference. It is NOT a stable attachment
identity, preview generation, approval token or proof of unchanged contents.
The current root importer retains its separate local legacy settings. Remote
once/remember consent must add attachment/preview binding and durable action
identity before any copying command is exposed. This read path cannot approve,
pause, remember, delete or change updates. A saved automatic-import setting is
shown as a setting, not actual activity or completion. Saved update access is
configuration presence, not proof of working credentials or a successful update.

## Verification

The same synthetic fixture in
`apps/android/app/src/test/resources/appliance-platform.json` is generated by the
Pi Java projection on host JVM and Android36, then parsed by Rust and Android
Kotlin tests. The projection rejects hostile counts/types and strips unrelated
private fields. Native QUIC tests exercise no-owner refusal before host access,
the approved read, other-peer refusal and revocation; direct tests exercise
revocation during a blocked read, overlap and absent/failed/invalid host data.
The Unix socket tests exercise real credentials, fixed read requests, truncated/
oversized/forged replies and a dripping response that cannot extend the deadline.

Actual native UI tests cover stale-data removal and200%text with partial versus
unknown observations. `docs/brand/interlink-storage-preview.png` uses example
data in the separate visual fixture: generic Application, native producers
omitted. It proves rendering/component behavior, not real node startup or native
production companion packaging. Normal native/package gates stay intact.

Exact counts, source hashes, commands, failures, Android API checks and cleanup
are in the private platform audit
`artifacts/validation/2026-10-31-platform-snapshot`. This is not installed Pi/
phone, real card/camera, cloud backup, roaming, migration or gold-image acceptance.
