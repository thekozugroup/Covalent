Covalent v0.1.0 — the first public alpha.

Covalent is a self-hosted backup and restore system for devices you already own.
It pairs devices directly over a LAN or Tailnet, stores encrypted verified chunks
only on devices you explicitly choose, and restores relative paths only beneath a
destination you authorize. There is no cloud service, no hosted account, and no
telemetry.

## What works in this release

- Signed device pairing and revocation over authenticated QUIC (transport v2).
- Streaming encrypted backup with content-addressed, verified chunks.
- Exact explicit replica placement — Covalent never picks storage for you.
- Corruption detection and repair.
- Signed restore preview, plus resumable restore confined to an authorized root.
- Crash recovery across the node, storage, and transfer layers.
- TLS-only management console and local API (persisted contract: protocol v1).
- Read-only source mappings, so a container can never write to a backup input.

## What is alpha

This is a `0.x` release and the on-disk and wire formats may change. Treat it as
something to evaluate, not as your only copy of anything that matters.

**Nobody has installed this yet.** Every claim above is backed by automated tests
and by the release gates listed under *Provenance* — not by field use. This build
has had no soak testing, no long-running deployment, and no real user. It is the
first artifact this project has ever published. Expect to find problems that CI
cannot see, and keep an independent copy of anything you cannot lose.

- Back up the `/data` appdata path separately. It holds identity and key state,
  and losing it means losing access to the encrypted chunks.
- The macOS build in this release is **not** notarized (see below).
- **No Android artifact is published in this release.** The Android app builds,
  passes its unit and instrumentation suites, and its release lane is complete,
  but publishing an APK requires a release signing keystore that does not exist
  yet. A signing key is a permanent identity — every future update must be signed
  by the same key or it will not install over the old one — so it is the
  maintainer's decision to create, not CI's. See *Android* below.
- **iOS and Windows are not supported and nothing in this release installs on
  either.** No iOS or Windows artifact is published. The repository contains an
  iOS target built from shared Apple sources, but it is unreleased and out of
  scope for now.
- Hosted accounts, automatic replica placement, and restores outside an
  authorized root are out of scope by design, not pending work.

## Install

### Unraid / Docker (Tier 1)

The container image is multi-architecture (`linux/amd64` and `linux/arm64`),
cosign-signed, and published with an SPDX attestation.

```sh
docker pull ghcr.io/thekozugroup/covalent:v0.1.0
```

Verify the signature before you run it — the digest and the exact command are in
`covalent-container-digest.txt` attached to this release:

```sh
cosign verify ghcr.io/thekozugroup/covalent:v0.1.0 \
  --certificate-identity-regexp '^https://github.com/thekozugroup/Covalent/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

On Unraid, add the template from
`packaging/unraid/covalent.xml`. Map each share you want backed up **separately
and read-only**, keep `/config` and `/data` on appdata, and set
`COVALENT_HTTPS_HOST` to the exact DNS name your clients will use. The console is
TLS-only; enroll the local CA from
`/config/caddy/data/caddy/pki/authorities/local/root.crt` before entering an API
token.

### macOS (Tier 1) — unsigned in this release

`Covalent-v0.1.0-macOS-arm64-unsigned.zip` is an Apple Silicon build. It is
**ad-hoc signed, not Developer ID signed and not notarized**, because this
project does not yet have an Apple Developer Program membership. Gatekeeper will
quarantine it, and that warning is accurate — you are trusting the checksum and
the build provenance below rather than Apple's review.

Verify it first. `Covalent-v0.1.0-macOS-arm64-unsigned.zip.sha256` records the
absolute path the file had on the build machine, so `shasum -c` will not find it
by that name — compare the hashes directly instead:

```sh
shasum -a 256 Covalent-v0.1.0-macOS-arm64-unsigned.zip
cat Covalent-v0.1.0-macOS-arm64-unsigned.zip.sha256
```

The two hashes must be identical. For this release it is
`6dab492e275fcfe32a2e9f6d05cef445176d2e0efee11f1193cdba4d18c1f916`.

Then either right-click the app and choose **Open** (and confirm once), or:

```sh
xattr -dr com.apple.quarantine /Applications/Covalent.app
```

Apple Silicon only. There is no Intel or universal build, and no auto-update.
A notarized build will replace this lane once a Developer ID certificate exists.

### Android (Tier 1) — not shipped in this release

**There is no Android download on this page.** Android is a Tier 1 platform and
its release lane (`android-release.yml`) is written, gated, and ready: it builds
a minified APK and AAB, signs them with the v1–v4 schemes, verifies the result
with `apksigner`, emits a CycloneDX SBOM and an R8 mapping, and checksums
everything. It has never been run, because it requires a release keystore that
this project has deliberately not created yet.

That keystore is a permanent identity. Once v0.1.0 ships signed by it, every
later Android update must be signed by the same key or Android will refuse to
install it, and losing the key means never shipping an update again. Generating
it is a one-time maintainer decision, not something a build pipeline should do on
its own. Until it exists, no Android APK will appear here.

If you want to run the Android app now, build it from source:

```sh
./gradlew -p apps/android assembleDebug
```

That produces a debug-signed APK, which will not upgrade to a future signed
release build.

## Provenance

Every artifact on this page was produced by a tagged GitHub Actions run from this
exact commit, gated on the full Tier 1 software suite plus a verified release
commit signature. Attached alongside the binaries:

- `covalent-container.spdx.json` — container SBOM (Syft, SPDX).
- `covalent-container-digest.txt` — the immutable multi-arch digest and the
  cosign command that verifies it.
- `covalent-container-SHA256SUMS.txt` — checksums for the two files above.
- `Covalent-v0.1.0-macOS-arm64-unsigned.zip.sha256` — checksum for the macOS zip.
- `Covalent-v0.1.0-macOS-dependency-inventory.tar.gz` — Apple dependency
  inventory, built with `SOURCE_DATE_EPOCH=0`.

### What the release commit signature does and does not prove

The gate requires that GitHub reports `verification.verified: true` for the
tagged commit. For this release that signature is **GitHub's own**: the release
commit was authored through an authenticated GitHub API call, and GitHub signed
it with its web-flow key. That proves the commit entered this repository through
an authenticated session on the maintainer's account. It does **not** prove that
a key held by the maintainer signed it, which is a stronger claim. Once a
maintainer SSH signing key is registered (see `docs/release/commit-signing.md`),
later releases will carry that stronger attestation instead.
