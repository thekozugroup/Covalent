# Covalent v0.2.0 release candidate

## Status

`v0.2.0` is not published. It has no signed tag, release assets, or replacement
container digest. The current personal-use scope is an unsigned/ad-hoc Apple
Silicon macOS package, a debug-signed Android APK, and Docker for Unraid or
other Docker hosts. Apple Developer ID/notarization is outside this personal-use release scope.
Android production signing is deferred.

## One-way links

Covalent now bundles rclone as its only transfer engine. A link sends one source
folder to one or more destinations. Destination changes never modify the source
or another destination. Separate contributors use separate link folders within a
shared collection, so files with matching names cannot overwrite one another.
Removing a link stops transfer work and preserves files.

Each authorized device shares one link configuration: Manual, Scheduled, or
Continuous timing, with Run Now available. Pending changes remain visible while offline. Android uses
system folder selection and reports operating-system conditions. macOS provides
native controls and per-link menu-bar status.

Deletion choices are independent:

- Source deletion keeps destination copies by default. An owner can opt in to
  deleting only copies created by that link.
- Destination deletion stays deleted by default. An owner can opt in to restore
  it from the source during a later transfer.

Missing mounts, permissions, or offline sources are errors, never empty
folders. See [product requirements](../../product/requirements.md) for exact
link, deletion, timing, and status behavior.

## Upgrade and safety

This is a `0.x` breaking release. Preserve an independently restorable copy of
Docker/Unraid `/config`, `/data`, and the separate owner-only KEK before
upgrading. Keep existing identity and token state with that recovery set. An
existing owned server remains owned; new ownership uses verified HTTPS claim and
CA enrollment. Key protection fails closed when its protector is missing, wrong,
or unavailable.

Upgrade active clients together: v0.1.0 transport v2 and v0.2.0 transport v3
are deliberately incompatible. Do not remove retained terminal receipts merely
to make room for more work. Use the [Unraid upgrade and recovery guide](../../platform/unraid.md#upgrade-and-recovery),
[Docker guide](../../../packaging/docker/README.md), and preserve that recovery set. Wait for the published immutable digest before
changing an Unraid template. Live appdata needs a stopped application or an
application-consistent snapshot; copying readable boot files does not establish
full boot recovery.

## Supported platforms

Tier 1 platforms are native arm64 macOS, native Android, Docker, and Unraid. Intel
macOS, iOS, and Windows are not published platforms. Docker does not bundle
Tailscale or access its LocalAPI socket; use deliberate routing and pairing.

Current transfer evidence includes a completed Atmos-to-Waypoint music transfer
with 7,344 files and 15,389,291,455 bytes. The post-upgrade unchanged run completes in 653.374 seconds, compared with
853.421 seconds before the source-scan simplification. This single comparison
is affected by filesystem caching and is not a throughput promise. The hourly
link preserves all source and destination files and stops transfer workers when
idle. Full release acceptance remains open; see the [completion ledger](../completion-progress.md).

## Release requirements

A verified signed commit and annotated `v0.2.0` tag, complete required CI,
current Mac package validation, tagged Android APK/device evidence, and draft
asset review are required before publication. Follow
[publishing.md](../publishing.md) for the exact release sequence.
