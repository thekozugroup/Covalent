# Covalent v0.2.12

This release brings the one-way folder links work to main and fixes Android sync
startup. Android now leads with saved links, showing source, destination, status
and settings together. New link guides pairing and source selection; receivers
choose their destination folder when accepting or repairing a share.

## Changes

- Recover a saved link removal after Android restarts the private sync service.
  Replay uses the exact authenticated offer and fresh endpoint, keeps the
  removal pending until acknowledgement is durable, and serializes interactive
  and startup requests. Removed links release their saved folder capability.

- Retain the native interface required by the minified Android app. Retry a
  restricted background-service start when the app becomes visible, and keep
  observing sync status across a local service restart or app update.
- Use the shared adaptive/themed icon, logo and serif Covalent title. Keep Back
  on secondary screens and move individual link settings into each card.
- Prefer a usable Tailscale address and refresh the node after network route
  changes. Nearby discovery holds Wi-Fi multicast permission independently of
  backup mode. Tailscale still requires its own authenticated connection.
- Preserve authenticated pairing identity when an address changes. Each
  destination keeps its own folder choice; shared cadence and deletion settings
  are reflected across the link. Destination deletions stay local by default.
- Include the earlier rclone folder-link runtime, macOS menu-bar controls,
  responsive server console, authenticated recipient metadata and durable SAF
  publication/recovery work from the production-readiness branch.
- Align native package versions and reject version drift reliably. Retain exact
  container security revisions, including Alpine Python 3.12.15-r0.

## Upgrade and scope

Version 0.2.12 follows the existing container-only 0.2.10 update. All native
packages use the same version so both container channels advance without
weakening downgrade protection.

The Android download is a minified, non-debuggable personal release APK. Its
certificate matches the recent Android appliance/mobile candidate, but differs
from the public v0.2.1 debug APK. Android rejects an in-place update from that
older download. The original private key is unavailable; preserve configuration
and folder grants before a deliberate migration. The release does not uninstall
or reset an existing app. See the accompanying Android upgrade note and build
receipt for both certificate fingerprints.

Keep existing app data, pairing identities and folder grants when updating.
Do not uninstall to work around a certificate mismatch without first preserving
configuration: Android requires the same signing certificate for an in-place
update. Personal-use Android packaging and ad-hoc signed, non-notarized macOS
packaging retain their stated limitations. Apple Developer ID and store release
are outside this release.

The earlier Android candidate was tested on a physical phone, including startup after
an in-place update and preservation of all 336 original Pictures files. Native
API 37 tests cover pairing, transfers, restart, address changes, permission
repair, shared settings and removal. Published asset receipts identify the
exact source and APK separately from any earlier candidate evidence.

This is a Covalent release, not certification of the GPhoto OS appliance. The
Pi's interrupted Pictures copy still requires safe journal recovery; full-folder
completion, phone-to-Pi nearby discovery and cellular handoff remain separate
acceptance checks. Sync completion does not confirm a Google Photos backup and
must not trigger deletion of originals.
