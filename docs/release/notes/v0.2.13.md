# Covalent v0.2.13

This release lets every client show which version a server runs, whether a
newer release exists and why a copy failed. Servers only report a newer
release; they never download or install it. The web console, Android and macOS
apps move to the KozuUI colours with plainer wording.

## Changes

- `GET /api/v1/status` now includes the node version. For callers with a valid
  access token it also includes the result of a notify-only daily check against
  the latest GitHub release. Set `COVALENT_UPDATE_CHECK=false` or pass
  `--update-check false` to turn the check off.
- A new `GET /api/v1/sync/run-failures` route gives a plain-language cause for
  this device's own failed copies. `/api/v1/sync/status` and the peer protocol
  are unchanged, so older clients and peers keep working.
- Web console: KozuUI colours and consistent link wording. Every request now
  has a timeout, so a stalled server no longer leaves a button pending. After
  unlock it shows the server version, any newer release and the cause of
  failed copies.
- Android: KozuUI theme and launcher tint, plainer pairing wording, the app
  version in Settings, and the cause of a failed copy. An older node keeps the
  plain Failed state.
- macOS: KozuUI tints, higher-contrast text, the node version, newer-release
  notices and the cause of failed copies.
- Container: Alpine build pins move to python3 3.12.16-r0 and git 2.52.1-r0.
  The runtime pins musl and musl-utils to 1.2.5-r24 and the signed
  ca-certificates-bundle 20261020-r0, with regenerated corresponding-source and
  notice evidence. Caddy and the rclone worker are built with Go 1.26.10, and
  Caddy moves to patched x/net, go-jose and klauspost/compress releases. No
  vulnerability is waived.
- Rust dependencies move to patched quinn-proto, rustls, rustls-webpki,
  webpki-root-certs, tokio, zip and rustix releases.
- The artifact budget check follows `CARGO_TARGET_DIR`. The README and
  CONTRIBUTING now point at `main`.

## Upgrade and scope

Keep `/config`, `/data`, the key-encryption key and the existing mounts when
updating a container. The new version and failure-cause fields are additions,
so mixed 0.2.12 and 0.2.13 peers keep working. A newer-release notice is
informational only; updates still come from the `stable` channel or a manual
image change. Personal-use Android packaging and ad-hoc signed, non-notarized
macOS packaging keep their stated limitations.
