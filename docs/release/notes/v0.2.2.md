# Covalent v0.2.2

This full release updates the shared node runtime and server console. It follows
the existing personal-use scope: Docker/Unraid, an ad-hoc Apple Silicon macOS
package, a debug-signed Android APK, and verified CLI packages.

## Pairing and shared folders

The server console groups one source folder with its recipients. Adding another
recipient reuses the retained source path and existing link settings. New
folders still require an explicit source selection, and mismatched source
paths are rejected. Device pairing continues to require matching codes on both
devices and retains the signed peer identity and certificate checks.

A newly added recipient can accept link settings established before its
invitation. Previously, the invitation's temporary timestamp could reject the
source's valid settings and leave that recipient waiting for a commit. Already
confirmed settings retain their rollback checks.

Docker and Unraid can show online Tailnet candidates through a bounded,
host-refreshed discovery file. The container needs no Tailscale socket or
privileged access. Candidates expire after three minutes; the console
distinguishes unavailable or expired discovery from a valid empty list.
See [Tailscale discovery setup](../../platform/tailscale-discovery.md). Automatic
candidates assume the standard peer port; custom published ports still require
an explicit address.

Owners can set local display names for known devices and folders through the
[display-name API](../../api/local-display-names.md). These preferences survive
restarts and updates without rewriting signed records. They are local to each
node and do not automatically propagate.

## Server access and updates

Trusted Tailscale HTTPS consoles can use the configured host proxy for automatic
access. The server console includes clearer device and folder actions, visible
pairing requests, and separate device names and folder labels. Normal Docker
and Unraid installations follow the signed stable container channel.

## Upgrade and release validation

Keep the existing configuration, data, separate KEK, share mounts, and published
ports when updating. Deletion defaults and existing link identities are
unchanged. Preserve a verified recovery copy before an upgrade.

This is a full release because shared runtime code changed. It must pass all
required checks on the exact signed release commit before an annotated signed
`v0.2.2` tag is created. Platform packages and publication follow the
[release runbook](../publishing.md); these notes do not claim new native device
or accessibility testing. A subsequent signed container tag at the validated
full-release commit updates the stable Docker channel. Existing release tags
remain immutable.
