# Covalent v0.2.3

This release updates the shared node runtime and server console. It retains the
existing personal-use packaging and signed release gates.

## Shared recipient lists

The source now sends authenticated share names and recipient lists to receiving
devices. Each WebUI can show the source and all recipients together. Local display
aliases remain local preferences. A receiver can stop receiving its own copy;
other recipients appear without management controls or invented live status.

The added status metadata is opt-in through the
`X-Covalent-Endpoint-Roster: 1` request header. Existing clients receive the
original response shape, including Android clients that reject unknown fields.
The roster carries presentation metadata, not a new trust grant or folder
capability.

Roster delivery validates the source, retained invitation, recipient, revision,
and bounded metadata. Removed shares and changes received while the sync engine
is stopping remain covered by the existing lifecycle and identity checks.

## Server console

Actions use slimmer pill-shaped controls and a muted slate palette. Touch input
retains comfortable targets. Serif headings, the quiet sidebar, Lucide icons,
and Covalent logo remain unchanged.

## Android folder safety

Concurrent uploads now coordinate folder metadata changes while file contents
continue streaming independently. Failed replacements preserve the original
file when Android reuses its document address during rollback. Transfer failure
diagnostics report fixed error categories without filenames or credentials.

## Upgrade and validation

Keep existing configuration, data, separate KEK, share mounts, and peer ports
when updating. This release does not change deletion defaults or replace the
existing share identity.

Shared runtime changes require a full native baseline. All required checks must
pass on the exact signed commit before the signed `v0.2.3` tag is created. The
subsequent signed `container-v0.2.10` tag updates the stable Docker channel through
the established build, scan, signature, and attestation workflow. Existing tags
remain immutable. These notes do not claim new local native UI or VoiceOver tests.
